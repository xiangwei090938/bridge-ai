# 应用管理页面 — 需求规范

## 1. 概述

### 1.1 目标
克隆 EchoBird 的"应用管理"页面到 Bridge AI，实现完全一致的 UI 结构、交互逻辑和数据流转。

### 1.2 用户故事
> 作为 Bridge AI 用户，我可以在"应用管理"页面中，查看本地已安装和未安装的 AI 工具，了解每个工具的详细信息，搜索和筛选工具，同步模型配置到已安装的工具，以及一键下载安装未安装的工具。

## 2. 功能需求

### 2.1 页面布局（三栏结构）
- **左侧主区域**：搜索栏 + 分类标签 + 工具卡片网格
- **右侧详情面板**：选中工具后的详细信息展示
- 左侧占主要面积，右侧详情面板固定宽度

### 2.2 搜索与筛选
- **搜索框**：在顶部，实时按工具名称筛选
- **分类筛选**：提供标签按钮组，包括 "全部"、"桌面端"、"IDE"、"CLI 命令行" 等分类
- **刷新按钮**：手动刷新工具列表

### 2.3 工具卡片网格
每个工具卡片显示：
- **图标**：每个工具有对应的图标/emoji
- **名称**：工具的人类可读名称
- **分类徽标**：工具所属类别
- **安装状态**：显示"已安装"或"未安装"
- **点击**：选中卡片，右侧显示详情

### 2.4 详情面板
选中工具后显示：
- **标题**：工具名称 + ID + 分类
- **安装状态**：已安装/未安装
- **安装路径**（如已安装）
- **API 协议**：支持哪些 API 协议（如 OpenAI、Anthropic）
- **模型配置同步**：如果工具支持同步，提供模型下拉选择 + 同步按钮
- **一键安装**：未安装工具提供安装按钮
- **操作日志**：同步/安装的操作记录

### 2.5 加载与空状态
- **加载中**：显示加载动画
- **空结果**：没有匹配工具时显示提示信息

## 3. 数据源

### 3.1 本地工具数据
从 Echobird 风格的工具目录加载数据：
- 每个工具一个子目录，包含 config.json 和 paths.json
- config.json：定义模型配置读写方式
- paths.json：定义平台安装路径、名称、分类、API 协议等

### 3.2 Mock 数据（开发阶段）
在 pi.ts 中已有完整的 Mock 数据覆盖所有场景。

## 4. 非功能需求
- 响应式布局，适配窗口大小变化
- 卡片网格使用 auto-fill 自适应列数
- 详情面板平滑过渡
- 操作日志实时更新
- 整个页面保持在 Tauri WebView 内运行，无外部跳转
